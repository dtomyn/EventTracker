# my-factory

A small software factory: `/my-factory <feature>` takes a feature from spec to build to four parallel reviews to approval and a merge into `main`.
The loop itself is documented in [skills/my-factory/SKILL.md](skills/my-factory/SKILL.md).

## Where things live

| Path | What it is |
|------|------------|
| `agents/` | Master copies of the factory's subagents. Edit these. |
| `skills/` | Master copies of the factory's skills, starting with the `my-factory` orchestrator. Edit these. |
| `sync.ps1` | Mirrors `agents/` and `skills/` into `.claude/` and `.agents/`. |
| `backlog.md` | Queue for `/my-factory next`. |
| `dashboard.html` | Live board that reads `board.json`. |
| `board.json`, `jobs/` | Runtime state written by the orchestrator (gitignored). |
| `ORIGINAL-PROMPT.md` | The prompt that produces this factory. |

## Changing an agent or skill

1. Edit the master file under `agents/` or `skills/`.
2. Run the sync from the repo root:

   ```powershell
   pwsh -File my-factory/sync.ps1
   ```

3. Commit the master and the generated copies together.

The copies in `.claude/agents`, `.claude/skills`, `.agents/agents`, and `.agents/skills` carry a "Generated by my-factory/sync.ps1" marker; do not edit them.
Every master name must start with `my-factory`, and its frontmatter `name:` must match the file or folder name.
The sync only writes and prunes `my-factory*` items, so other agents and skills in those folders are left alone.
Run `pwsh -File my-factory/sync.ps1 -Check` to verify the copies are current without changing anything (exit code 1 on drift).

## Dashboard

From the repo root:

```powershell
uv run python -m http.server 8765 --bind 127.0.0.1 --directory my-factory
```

Then open http://127.0.0.1:8765/dashboard.html.
